# Database Migration Safety

## Scope

Применять ко всем изменениям схемы, миграциям и проверкам рабочей `MasterLibrary.db`.

## Mandatory Rules

- До изменения определить фактический путь рабочей `MasterLibrary.db`.
- Создать резервную копию перед применением migration.
- Добавлять новую migration; не переписывать уже применённую.
- Проверять migration history до и после применения.
- Проверять migration на копии существующей базы с реальными данными.
- Сохранять существующие данные и обеспечивать повторяемое безопасное применение.

## Forbidden

- Удалять, очищать или пересоздавать рабочую `MasterLibrary.db` для исправления migration.
- Тестировать migration только на пустой новой базе.
- Менять старую migration после её применения.
- Удалять production data без отдельного явного решения владельца.
- Использовать `SMT.db` как замену Master Library.

## Workflow

1. Найти активную `MasterLibrary.db` и проверить migration history.
2. Сделать датированную резервную копию.
3. Создать новую идемпотентную или корректно версионированную migration.
4. Применить её к копии существующей базы.
5. Проверить схему, данные, ограничения и повторный запуск.
6. Только после успешной проверки применять к рабочей базе.

## Verification

- Существующие записи сохранены.
- Migration history содержит ожидаемую версию ровно один раз.
- Ограничения целостности выполняются, включая единственность текущего verified dataset.
- Резервная копия доступна и рабочая база не удалялась.
